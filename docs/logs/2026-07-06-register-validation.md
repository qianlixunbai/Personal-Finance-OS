# 開発ログ（2026-07-06）：登録失敗の調査

## 目的

フロントエンドの登録フローで発生した「登録失敗」を調査し、プリセットアカウントやバックエンド異常の有無を確認する。

## 症状

- 登録ページで送信すると、すぐに「登録失敗」と表示される。
- プロジェクトにプリセットアカウントがあるように見えた。

## 調査結果

1. このプロジェクトにはプリセットのログインアカウントはない。
2. バックエンドの登録 API は通常どおり `200 success` を返せる。
3. 実際の原因はユーザー名のバリデーションだった。

## 根本原因

バックエンドの登録リクエストモデルでは以下が必須:

- `username` は 3 文字以上 50 文字以下
- `password` は 6 文字以上

今回入力されたユーザー名は 2 文字しかなかったため、バックエンドでバリデーションエラーになった。

## 対応手順

1. フロントエンドの登録・ログイン要求が `/api/v1` 経由であることを確認した。
2. Vite が `http://localhost:8080` へプロキシしていることを確認した。
3. バックエンドの登録 API を直接呼び出して応答を確認した。
4. `RegisterRequest` のユーザー名長制約に原因を特定した。

## 影響範囲

- 登録フォームの失敗理由の理解にのみ影響する。
- バックエンドのビジネスロジック変更は不要だった。
- データベース変更も不要だった。

## リスク

- フロントエンドでは、バックエンドのバリデーション失敗を一律に「登録失敗」と表示しており、やや分かりにくい。
- より分かりやすいエラーマッピングは後から追加できるが、今回の修正範囲外。

## 検証

- バックエンドの登録 API は `200 success` を返せる。
- ユーザー名が 3 文字以上なら登録できる。

## 結論

プリセットアカウントが足りないのではなく、ユーザー名が短すぎたのが原因だった。今後は登録時のユーザー名を 3 文字以上にする。
