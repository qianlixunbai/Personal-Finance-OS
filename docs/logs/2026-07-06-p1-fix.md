# Development Log (2026-07-06): P1 Fixes

## Goal

Fix only the confirmed P1 issues from Review, without handling P2, changing the database schema, or modifying the frozen Architecture document.

## Scope

This fix covers the following P1 issues:

- Incorrect account deactivation behavior.
- Hardcoded database credentials and JWT secret in configuration.
- MyBatis stdout SQL logging enabled.
- Login not checking user status.
- JWT old tokens not rechecking user status.
- Asset price updates missing positive-value validation.

## Process

1. Adjusted `AccountService` deactivation logic: deactivation is allowed even when there is transaction history; deletion remains forbidden.
2. Updated `application.yml` to use environment variables for database credentials and JWT secret.
3. Disabled MyBatis stdout SQL logging.
4. Updated `UserService` so login checks the user `status`.
5. Updated `JwtAuthFilter` to recheck user status after token validation so disabled users cannot keep using old tokens.
6. Updated `AssetController` and `AssetService` so `updatePrice` requires `price > 0`.
7. Added unit tests for the key fixes.

## Impact

- Account module: deactivation now matches the business rule and no longer blocks because of transaction history.
- User module: disabled users cannot log in.
- Authentication module: disabled users cannot keep accessing protected resources with old tokens.
- Asset module: asset price updates now enforce positive values.
- Configuration: sensitive values are no longer hardcoded in the config file.

## Risks

- Deployment environments must provide the database username, database password, and JWT secret through environment variables.
- Disabled users' old tokens become invalid immediately, which is expected security behavior.
- Test coverage is focused on the P1 fixes and does not expand to P2.
