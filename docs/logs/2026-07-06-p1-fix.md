# 開発ログ（2026-07-06）：P1 修正

## 目的

Review で確認済みの P1 問題のみを修正し、P2 は扱わない。データベーススキーマを変更せず、凍結済みの Architecture 文書も変更しない。

## 対象範囲

今回の修正対象 P1 は以下の通り:

- 口座の停用ロジックが不適切。
- 設定ファイルにデータベース認証情報と JWT secret がハードコードされている。
- MyBatis の stdout SQL ログが有効になっている。
- ログイン時にユーザー状態を検証していない。
- JWT の古い token でユーザー状態を再確認していない。
- 資産価格更新で正数チェックがない。

## 対応手順

1. `AccountService` の停用ロジックを調整し、取引履歴があっても停用可能、削除は不可とした。
2. `application.yml` を更新し、データベース認証情報と JWT secret を環境変数参照に変更した。
3. MyBatis の stdout SQL ログを無効化した。
4. `UserService` を更新し、ログイン時に `status` を確認するようにした。
5. `JwtAuthFilter` を更新し、token 検証後にユーザー状態を再確認するようにした。
6. `AssetController` と `AssetService` を更新し、`updatePrice` で `price > 0` を必須とした。
7. 主要な修正に対する単体テストを追加した。

## 影響範囲

- 口座モジュール: 停用が業務ルールに一致し、取引履歴の有無で停止できなくなる問題を解消。
- ユーザーモジュール: 無効ユーザーはログイン不可。
- 認証モジュール: 無効ユーザーは古い token でも保護リソースにアクセスできない。
- 資産モジュール: 資産価格更新で正数制約を導入。
- 設定管理: 機密情報を設定ファイルへハードコードしないようにした。

## リスク

- デプロイ環境では、データベースユーザー名、データベースパスワード、JWT secret を環境変数で提供する必要がある。
- 無効化されたユーザーの古い token は即時無効になるが、これは想定どおりの安全挙動。
- テストカバレッジは P1 修正に集中しており、P2 までは拡張していない。
