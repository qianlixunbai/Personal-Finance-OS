# v3.0 Phase 2B Overall Closing Review

## Scope and closure decision

Phase 2B closes the investment write foundation that follows the v3.0 ledger foundation and Phase 2A account-balance concurrency work. Its completed scope is:

- investment projection safety and precision;
- user-scoped Instrument and Account/Asset binding;
- single-Asset Legacy opening migration;
- manual BUY, SELL, and DIVIDEND posting;
- append-only standalone reversal;
- replacement command envelope, canonical replay foundation, and replacement write path;
- atomic Account.balance mutation, transaction-driven Asset projection, immutable receipts, and append-only audit;
- idempotency, deterministic locking, lock timeout/deadlock mapping, unknown-commit recovery, and PostgreSQL migration/runtime verification.

This is an administrative aggregation of the completed leaf phases. It does not re-review or alter their accepted implementations.

## Current investment-module capability

The repository now provides user-scoped Instruments; unique Account/Instrument/Asset binding; authenticated Legacy opening migration; BUY, SELL, and DIVIDEND posting; weighted-average-cost full-history position replay; Position close and reopen; atomic Account.balance mutation; transaction-driven Asset projection; append-only standalone reversal; replacement correction; immutable original facts, receipts, and correction commands; request hashing and idempotency recovery; deterministic locking; safe lock-timeout/deadlock mapping; unknown-commit recovery; canonical replay anchors; replay trace and digest; PostgreSQL 17.10 integration coverage and V13 runtime verification.

## Explicitly outside Phase 2B

The following are not implemented, but do not block this closure: Portfolio-specific read model/API; user-facing InvestmentTransaction query, detail, or audit-timeline API; investment frontend; Position detail or correction UI; historical position snapshots; historical prices; return curves; multi-currency accounting; FIFO/lot accounting; corporate actions; broker or exchange integration; and AI Agent capability.

## Retired or superseded directions

- A generic InvestmentTransaction write endpoint is superseded by the implemented type-specific APIs.
- Updating an original fact or treating `REVERSED` status as the correction model is superseded by append-only reversal and replacement.
- The earlier `replaces_transaction_id` direction is no longer applicable.
- Phase 2B-4 and Phase 2B-5B must not be re-opened merely to duplicate their already closed child work.
