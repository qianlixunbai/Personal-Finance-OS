## 已确认实现与不变量

- `POST /api/v1/investment/transactions/{transactionId}/replacement` 解析原始事实类型，并在调用 replacement 命令路径前拒绝未知字段。
- 事务 Service 按确定性顺序锁定原始事实、account、instrument、asset 与 same-key 纠正命令。在开放任何 duplicate-key 恢复路径前，它会验证规范 request hash 与不可变回执。
- Replacement 成功时插入分组冲正与替换事实，恰好应用一次合并后的账户 cash delta，根据 replay 计算并持久化 Asset 投影，最后插入纠正命令，并在提交前运行一致性 checker。
- Checker 验证分组事实、回执链接、trace / digest、account balance、asset projection、reference value 与纠正命令回执字段。Checker 触发的失败会回滚整个事务。
- PostgreSQL `55P03` lock-not-available 与 `40P01` deadlock 错误映射为 HTTP 409。精确的命名 constraint 处理区分 same-key / same-hash 回执 replay 与 same-key / different-body 冲突。
- Price-update 并发场景发现的生产竞态通过在计算参考市值前锁定用户拥有的 Asset 关闭。相关单元测试现模拟同一锁定查询；行为仍仅涉及参考价格，不改写交易驱动投影。

## PostgreSQL 并发与恢复证据

全部集成覆盖使用 Testcontainers `postgres:17-alpine`；观察到的 server 报告 PostgreSQL **17.10**。并发测试在真实 replay 边界使用 latch，并通过 `pg_stat_activity` 验证 PostgreSQL 锁等待；不使用仅靠 sleep 的竞态断言。每个测试都通过全新连接读取最终状态，验证 replay 后的投影，并确认没有残留等待锁。

- `InvestmentReplacementConcurrencyIntegrationTest` 覆盖 same key / same hash 回执 replay；same key / different hash 冲突；同一原始事实使用不同 key；与 reversal、buy、sell、dividend、reference-price update、account deactivation、instrument inactivation，以及共享一个 asset 的两个原始事实之间的竞态。它还覆盖竞争命令执行后候选变为超卖的场景。
- `InvestmentReplacementLockIntegrationTest` 覆盖原始事实、account、instrument、asset 与现有纠正命令的锁等待超时，以及一个真实 PostgreSQL deadlock。每项都验证 HTTP 409 / SQLSTATE 行为、回滚、锁释放和成功重试。
- `InvestmentReplacementUnknownCommitIntegrationTest` 覆盖已提交但响应丢失的事务、已回滚但响应被遮蔽的事务，以及不确定完成后的 different-body 行为。已提交事务的重试返回旧的不可变回执，而不是当前余额或 asset 状态。
- `InvestmentReplacementFailureIntegrationTest` 在 replay、分组事实持久化、account 变更、第二次 replay / trace / digest、投影、命令持久化、数据库 constraint 与一致性 checker 篡改等阶段注入失败。全新连接快照证明精确回滚且没有等待锁。
