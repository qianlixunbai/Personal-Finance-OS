## Final closing update — 2026-07-28

The preceding **NO-GO** record is retained as historical evidence: at that point the remaining hard-blocker matrix had not been executed. This update records the later implementation and verification; it does not rewrite the earlier conclusion.

### Resolved hard blockers

- **PostgreSQL deadlock victim:** `InvestmentDividendLockIntegrationTest.dividendIsPostgresDeadlockVictimAndRollsBackWhileReverseLockTransactionSurvives` creates a real reverse lock cycle. The helper transaction holds `Asset` then waits for `Account`; DIVIDEND retains the production `Account → Instrument → Asset` order, receives PostgreSQL SQLSTATE `40P01`, maps safely to HTTP 409, and rolls back. The helper transaction commits successfully.
- **First replay failure:** the injected Spring spy fails the initial replay before a DIVIDEND fact is inserted; the transaction remains unchanged.
- **Second replay failure:** the first replay runs normally, then the injected second replay fails after fact insertion and balance mutation; the entire transaction rolls back.
- **Projection row count:** `AssetMapper.updateTransactionDrivenProjection` returns `int`; DIVIDEND requires exactly one affected row inside its `@Transactional` boundary. A local Mapper spy returning zero produces a safe HTTP 500 and rolls back the fact, receipt, balance, and projection.
- **Cash consistency:** a PostgreSQL `BEFORE UPDATE` mutation of `accounts.balance` is detected because the checker now receives the persisted account balance, not only the in-memory mutation result.
- **Receipt consistency:** a PostgreSQL `BEFORE INSERT` mutation of a valid-looking DIVIDEND receipt is detected because the checker now re-reads the inserted receipt in the same transaction before it returns.
- **Position metadata consistency:** a PostgreSQL `BEFORE UPDATE` mutation of `assets.last_transaction_id` is detected by the checker and rolls back.
- **Unknown unique constraint:** idempotent recovery is now restricted to PostgreSQL constraint `uk_investment_transactions_user_idempotency` with SQLSTATE `23505`. An injected unique index on `external_reference` is not treated as an idempotent replay, returns no receipt data, and leaves no duplicate or partial write.

Every failure scenario re-queries the database outside the request transaction and asserts no new DIVIDEND/receipt, original Account balance, unchanged Position quantity/average cost/total cost/realized P&L/status/last transaction/projection version/current price/market value, and unchanged Account/Instrument binding. HTTP 500 responses do not expose balances, DIVIDEND amounts, request hash, idempotency key, SQL, Mapper/constraint names, or stack traces.
