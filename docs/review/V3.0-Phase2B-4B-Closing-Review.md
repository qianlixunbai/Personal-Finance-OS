### 已解决的硬阻塞项

- **PostgreSQL 死锁牺牲事务：** `InvestmentDividendLockIntegrationTest.dividendIsPostgresDeadlockVictimAndRollsBackWhileReverseLockTransactionSurvives` 创建真实反向锁循环。辅助事务持有 `Asset` 后等待 `Account`；DIVIDEND 保持生产 `Account → Instrument → Asset` 顺序，收到 PostgreSQL SQLSTATE `40P01`，安全映射为 HTTP 409 并回滚；辅助事务成功提交。
- **第一次 replay 失败：** 注入的 Spring spy 在插入 DIVIDEND 事实前使首次 replay 失败；事务保持不变。
- **第二次 replay 失败：** 第一次 replay 正常执行，注入的第二次 replay 在事实插入和余额变更后失败；整个事务回滚。
- **投影行数：** `AssetMapper.updateTransactionDrivenProjection` 返回 `int`；DIVIDEND 在其 `@Transactional` 边界内要求恰好影响一行。本地 Mapper spy 返回零时产生安全的 HTTP 500，并回滚事实、回执、余额和投影。
- **现金一致性：** PostgreSQL `BEFORE UPDATE` 对 `accounts.balance` 的篡改可被检测，因为 checker 现在接收持久化后的账户余额，而不只是内存变更结果。
- **回执一致性：** PostgreSQL `BEFORE INSERT` 对外观有效 DIVIDEND 回执的篡改可被检测，因为 checker 在返回前会在同一事务中重新读取已插入回执。
- **Position 元数据一致性：** PostgreSQL `BEFORE UPDATE` 对 `assets.last_transaction_id` 的篡改会被 checker 检测并回滚。
- **未知唯一约束：** 幂等恢复现在仅限 PostgreSQL 约束 `uk_investment_transactions_user_idempotency` 与 SQLSTATE `23505`。注入到 `external_reference` 的唯一索引不会被视为幂等 replay，不返回回执数据，也不会留下重复或部分写入。

每个失败场景都在请求事务外重新查询数据库，并断言：没有新增 DIVIDEND / receipt；Account 保持原始余额；Position quantity / average cost / total cost / realized P&L / status / last transaction / projection version / current price / market value 保持不变；Account / Instrument 绑定保持不变。HTTP 500 响应不暴露余额、DIVIDEND 金额、request hash、幂等键、SQL、Mapper / constraint 名称或 stack trace。
