# v1.5 Deployment Readiness Closing Review

## 1. Goal

v1.5 adds a minimal, reproducible single-host deployment path without changing business models, database structure, Flyway migrations, or the frozen architecture. The target path is:

```text
build images -> Docker Compose -> PostgreSQL -> backend -> frontend Nginx -> browser
```

## 2. Delivered scope

- Added Spring Boot Actuator as the only new application dependency.
- Added a `prod` profile with required datasource properties, disabled Springdoc endpoints, health-only Actuator exposure, liveness/readiness groups, database-aware readiness, and graceful shutdown.
- Allowed only `/actuator/health` and `/actuator/health/**` through Security; business APIs and non-health Actuator paths remain authenticated.
- Added a PostgreSQL Testcontainers integration test for anonymous health probes, protected API boundaries, and hidden health details.
- Added multi-stage backend and frontend Dockerfiles plus narrow Docker ignore files.
- Added Nginx SPA fallback, same-origin `/api/*` forwarding, and host-accessible `/actuator/*` forwarding.
- Added Docker Compose for PostgreSQL 17, backend, frontend, backend readiness health, frontend health, and a named PostgreSQL volume.
- Added Secret templates and ignore rules. Real values are neither stored in Dockerfiles nor in Compose.
- Added a CI deployment-artifacts job that builds both images and parses Compose without registry login, push, deployment, new Secrets, or broader permissions.
- Added the deployment guide and documentation navigation.

## 3. Deployment topology

```text
Browser
  -> Frontend Nginx
      - React static files and SPA fallback
      - /api/* and /actuator/* -> Spring Boot backend
                                      -> PostgreSQL 17
```

The frontend still uses its existing relative `/api/v1` base URL. No CORS policy or Vite production API address was introduced.

## 5. CI status

The workflow now includes the local-equivalent deployment-artifacts checks:

```text
docker build -t finance-os-backend:ci ./backend
docker build -t finance-os-frontend:ci ./frontend
docker compose --env-file docker/.env.example -f docker/compose.yml config
```

No GitHub Actions run has been started in this review because this work has not been committed or pushed. Therefore, remote CI success is pending and must be verified after a user-authorized push.

## 7. Known limitations

- No HTTPS, domain, cloud deployment, registry publishing, or automatic CD.
- No automated backups, restore workflow, high availability, external monitoring, or log platform.
- No browser E2E framework or full Compose startup in CI.
- No multi-origin frontend/backend deployment; the supported topology is same-origin Nginx proxying.
