## 本轮 Reload Recovery P1 remediation

- 独立 Closing Review 发现 P1：plain persisted `RECOVERING_CONFIRM` 在 reload 后没有降级为 `OUTCOME_UNKNOWN`，恢复会绕过 Receipt GET 而直接 POST。
- root cause：startup normalization 只覆盖 `SUBMITTING` 与 `RECOVERING_LOOKUP`，遗漏 `RECOVERING_CONFIRM`。
- remediation：plain `RECOVERING_CONFIRM` 在 startup/reload 规范化为 `OUTCOME_UNKNOWN`，因此下一次 recovery 必须 Receipt GET-first；GET 404 后才以同一 frozen intent fallback POST。
- `AUTH_REQUIRED(resumeState=RECOVERING_CONFIRM)` 不属于 plain startup record，继续按同用户认证 continuation 处理：消费 `resumeState` 后获得干净的 `RECOVERING_CONFIRM`，并直接恢复同一 POST。
- 新增真实浏览器 reload E2E 在 fallback POST 尚未确定完成时执行 `page.reload()`；它独立记录 reload 后 recovery 请求，断言严格 `GET → POST`，并逐项断言 reload 后 POST 与首次/fallback POST 的相同 `Idempotency-Key`、path 与 `bodyJson`。该场景稳定运行 `20 / 20 PASS`。

## D 关键证据

### Receipt reload

- 真实 `/transactions/import/receipts/:batchId` `page.reload()` 每次重新 GET 权威回执；不依赖 React memory、Confirm response 或本地 Receipt 内容。
- `9007199254740993.01`、`-0.01`、`9007199254740993.00` 在 reload 前后保持精确字符串。
- reload 后 GET 401：只保存同用户的 batch route identity（不保存回执/金额），同用户登录后回到原 route 并再次 GET；零 Confirm POST。
- reload 后 GET 404：仅显示安全 not-found，零 Confirm POST。
- 101 条 transaction refs 只渲染当前 100 条，支持键盘可达的上一页/下一页及范围提示。

### Multi-tab Confirm

两张真实 Browser Page 在同一 Session、同一 frozen Preview 上并发触发 Confirm。Web Lock 与 shared pending 保证仅产生一个 frozen intent；获锁者可以是任一标签。所有捕获的 Confirm POST 只有一个，并断言唯一 `Idempotency-Key`、固定 path 与精确 `bodyJson`。该场景额外稳定运行 `20 / 20 PASS`。

### CSV / XLSX 全流程

CSV 与 XLSX 都覆盖：Upload → 同一 Session 两次 Mapping PUT → discovery → formal mapping → server Preview → warning 显式 acknowledgement → Confirm → Receipt → Receipt reload。测试断言：仅一次 upload、两次 PUT 都使用同一 Session、revision 后重新加载 rows/warnings、未确认 warning 不可 Confirm，以及完整 flow 中的转义服务端文本。

## 不变量复核

- 后端是余额、Preview、warning、duplicate 和 Receipt 的唯一权威；前端不做余额聚合、重复判断或 warning ID 生成。
- Confirm 只发送冻结 token 与后端 warning IDs；同一 intent 保持相同 key/path/body。
- committed 状态单调，unknown recovery 先 GET，只有符合 Contract 的 404 才能恢复同一 POST。
- Receipt 金额使用 lossless transport 的字符串，不转换为 JavaScript Number。
- 草稿、pending、Receipt 登录返回均绑定用户；用户切换、logout unresolved、四条 401 与 14 个 domain code regression 继续由浏览器套件覆盖。
