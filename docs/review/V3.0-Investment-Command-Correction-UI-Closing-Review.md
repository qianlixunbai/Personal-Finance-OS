## Replacement 三方证据不变量

恢复 `REPLACEMENT` 写入前必须重新读取权威原始交易 subtype，并验证：

```text
authoritative original subtype
==
persisted originalTransactionType
==
explicit replacementRequestType
```

任何 `missing`、`unknown`、读取失败或三方不一致均 fail-closed，`resumed replacement financial POST == 0`。三方一致时，锁内恢复只允许一次写入。

## 401 Auth Resume

首次 `REPLACEMENT POST` 收到 `401` 后，即使记录为 `AUTH_REQUIRED + resumeState=SUBMITTING` 且 recovery classification 为 `INITIAL_POST`，重新认证后的 replacement financial POST 也会在真正发送前通过权威证据校验。

`INITIAL_POST` 不再构成 replacement resumed write 的旁路；非 replacement 的 `AUTH_REQUIRED + SUBMITTING` 仍保留首次提交语义，不会被改写为 unknown-outcome recovery。
