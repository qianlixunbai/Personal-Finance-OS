# v3.0 Phase 2B-1 Closing Review — 投资投影安全与精度

## 范围

本阶段使受控 Asset 投影与现有投资账本保持一致，不新增任何投资写 API、Opening Position migration、Account.balance 联动、Portfolio UI 或历史快照。

## 验收证据

| 要求 | 结果 | 证据 |
| --- | --- | --- |
| 全新数据库 migration | PASS | PostgreSQL 17 Testcontainers 执行 V1 至 V6。 |
| V5 升级 migration | PASS | V5 schema 升级到 V6，同时保留现有 LEGACY Asset 行。 |
| quantity 精度 | PASS | `assets.quantity` 为 `NUMERIC(28,8)`，并保留八位小数边界值。 |
| avgCost 精度 | PASS | `assets.avg_cost` 为 `NUMERIC(28,8)`，并保留八位小数边界值。 |
| 金额精度 | PASS | 账本事实金额列继续使用 `NUMERIC(28,2)`；公式和金额 scale 均未改变。 |
| LEGACY Asset 兼容性 | PASS | 现有关闭与零数量删除行为继续有测试覆盖。 |
| 交易驱动关闭保护 | PASS | Asset 关闭在修改任何投影字段前返回业务冲突 `409`。 |
| 交易驱动删除保护 | PASS | Asset 删除在物理删除前返回业务冲突 `409`。 |
| 参考价格边界 | PASS | 交易驱动 Asset 仍可更新参考价格，且不改变受控投影字段。 |
| Replay 时间 | PASS | Replay 边界为 `Instant`；持久化已经使用 `TIMESTAMPTZ`。 |
| 稳定 replay 顺序 | PASS | Replay 与 Mapper 测试均验证 `trade_time ASC, id ASC`。 |
| 用户范围 | PASS | Mapper 查询包含 `user_id`；PostgreSQL 集成测试证明不会返回跨用户行。 |

## 验证

- 定向 migration 测试：`FlywayMigrationIntegrationTest` 与 `FlywayVersionFiveUpgradeIntegrationTest` 使用 PostgreSQL 17 Testcontainers 并通过。
- 定向写入安全测试：`AssetServiceTest`（10 tests）与 `AssetControllerWebMvcTest`（13 tests）通过。
- 定向 replay 与 repository 测试：`InvestmentReplayEngineTest`（10 tests）与 `InvestmentTransactionMapperPostgresIntegrationTest`（6 tests）通过。
- 完整后端验证：`./mvnw.cmd clean test` 完成 64 test classes、281 tests、0 failures、0 errors、0 skipped tests。
- 阶段提交前要求执行 `git diff --check` 与 `git diff --cached --check`。

## 范围确认

本阶段未实现：`investment_instruments`、Instrument 到 Position 绑定、Legacy Asset Opening Migration、InvestmentTransaction 写入 / 冲正 API、幂等写工作流、Account.balance 联动、Portfolio API / UI、Dashboard 变更、`sites-demo` 变更、历史价格、快照、多币种账务、FIFO / LIFO、Redis、MQ、微服务或 AI。

## 已知限制

- 交易驱动投影写入仍刻意推迟到后续投资命令与 replay 路径；本阶段只阻止现有 Asset API 覆盖或删除这些投影。
- `trade_time` 是现有 schema 中 replay 时间戳的名称；它继续使用 PostgreSQL `TIMESTAMPTZ`，并以 `id` 作为确定性的次级排序键。

## 结论

GO。定义的 Phase 2B-1 范围内没有剩余 P0 或 P1 问题。
