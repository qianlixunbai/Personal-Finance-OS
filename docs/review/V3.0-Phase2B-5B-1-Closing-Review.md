## PostgreSQL 发现与实现修正

真实 PostgreSQL 验证发现了此前 Docker 不可用时无法覆盖的两个缺陷：

- V13 构建了一个预期 V12 的临时表，并为其添加指向永久 `assets` 与 `accounts` 的外键；PostgreSQL 拒绝此操作，因为临时表约束只能引用临时表。V13 现在直接从 `pg_constraint` 校验五个跨表 V12 外键，包括被引用表以及有序的本地 / 引用列，同时保留现有快速失败要求。
- MyBatis 没有处理 PostgreSQL `UUID` 纠正组参数 / 结果映射的 handler。`correction_group_id` 现在显式使用 `PostgresUuidTypeHandler`，使 application-context migration 验证使用真实 PostgreSQL UUID 值。

Fixture 修复使用生成的纠正事实标识符代替依赖 sequence 的字面值，保留延迟外键断言，并更新两个“latest migration”断言仍为 V12 的历史升级测试。没有放宽任何 constraint、trigger、延迟关系或快速失败行为。

首次最终只读审查随后发现，新目录表驱动的外键 verifier 存在一个 P1 缺口：没有比较目标 schema，也没有比较 FK action / match / deferrability / validation 语义。V13 现在还要求全部五个 V12 外键使用 `public` 目标 schema、`NO ACTION` update / delete 行为、`MATCH SIMPLE`、不可延迟且非 initially deferred，并且 constraint 已验证。一个 PostgreSQL 回归用 `ON DELETE CASCADE` 重建 `fk_investment_transactions_user_asset`，证明 V13 会在任何 schema 变更前拒绝执行。
