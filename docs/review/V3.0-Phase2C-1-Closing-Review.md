## 4. 事实来源与当前模型

复审交叉核对了当前 Java model / mapper / replay engine、V4–V13、ADR-007 至 ADR-014、Phase 1/2A/2B 各 Closing Review，以及当前 Rules / Database / API 文档。结论为：

- `InvestmentTransaction` 是不可变投资物理事实；
- transaction-driven `Asset` 是唯一当前 Position 受控投影；
- `Account.balance` 是当前现金投影；
- `InvestmentTransactionCorrection` 是 replacement 命令的不可变完整封装；
- posting-time receipt 是历史快照，不是纠正后当前真值；
- replacement 没有独立 transaction type，由 grouped reversal、同类型 replacement fact 和 envelope 组成；
- canonical replay key 为 `(effectiveTradeTime, effectiveAnchorId, replaySequence, factId)`。

## 5. 已分析的核心方案

### Portfolio 数据来源

比较了当前表/投影组合、持久化 read-model 表、请求时完整 replay。采用当前表与受控投影组合；拒绝第二套 Position 真值和逐请求完整 replay。

### 交易列表表达

比较了全部物理事实、仅逻辑事件、默认逻辑事件 + 独立审计层。采用双层模型：默认列表不重复展示 correction facts，审计层保留全部物理关系。

### Legacy Asset

比较了仅 transaction-driven、混合 Legacy、Legacy 仅保留 Asset API。最终 Portfolio 只包含 transaction-driven Position；Legacy Asset 继续由现有 Asset API 表达。

### 分页

比较了现有 offset `page/size` 与 opaque cursor seek。Position 和 transaction list 采用完整稳定排序键的 cursor；Portfolio summary 与当前有界 audit timeline 不分页。

## 6. 最终冻结契约

- Portfolio 是可审计的 transaction-driven 投资组合，不代表全部资产或净资产。
- Position 当前值来自 canonical replay + 当前受控 Asset projection；客户端不得重算。
- 默认 transaction list 每个 original logical slot 最多一条，状态为 `UNCHANGED`、`REVERSED` 或 `REPLACED`。
- Standalone reversal 默认标记 original 为 `REVERSED/effective=false`；reversal fact 在详情/审计层展示。
- Replacement 在 original logical slot 展示 replacement 后有效值；grouped reversal 不作为普通外部交易。
- Grouped reversal 的空 receipt 是 `NOT_APPLICABLE`；完整 replacement 结果来自 correction envelope。
- Audit timeline 按真实事件时间展示 physical facts 和 command，默认列表仍按 effective business time 排序。
- Current truth、posting-time receipt 与 correction final receipt 是三个不同概念。
- 交易逻辑列表按 `(effectiveTradeTime DESC, logicalTransactionId DESC)`；Position list 使用稳定 ID 复合键；两者均采用 opaque cursor。
- Reference valuation 摘要固定存在但 value 可缺失；只读缓存，显式 freshness/coverage/warning，不污染账务真值。
- 多查询组合使用只读 `REPEATABLE READ` 保证单请求内一致读取；普通 GET 不加行锁、不写状态、不调用 Provider。

## 7. 候选 API 与字段边界

冻结六项候选读取能力：Portfolio summary、Position list/detail、逻辑 transaction list/detail、audit timeline。所有 endpoint 要求 JWT 和数据库层 user ownership；跨用户与不存在资源统一安全 404。

允许公开当前 Position 金融值、用户拥有的 Account / Instrument display 信息、逻辑 correction status、必要的详情/审计关联和历史回执。禁止公开：

- `projectionVersion`、`lastTransactionId`；
- request hash、完整 idempotency key；
- replay digest、内部 trace；
- correction group ID；
- password/security、SQL、constraint、内部类名和堆栈。
