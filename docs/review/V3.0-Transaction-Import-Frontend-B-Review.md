## 2. 实现范围与权威边界

- Preview summary 与每一行 validation/error/warning 均直接显示服务端 response；前端不重新计算金额、duplicate 或金融结果。
- 可见表格固定保存当前服务端页（`size=100`）；warning hydration 以 `size=500` 顺序扫描，并只长期保留去重后的服务端 warning metadata。
- warning acknowledgement 只接受服务端 warning ID；全部当前 warning 分组显式确认且没有 error row 时才显示 `Ready to confirm`。该状态没有 Confirm 控件，也没有 Confirm 请求。
- 新 revision、返回 Mapping、Cancel、unmount 都使旧 hydration identity 失效。迟到 response 不得写入新的 Preview、warning、acknowledgement、loading 或 workflow state。
- Cancel 409 清除草稿并进入 `RECOVERY_REQUIRED`；不会猜测 `CONFIRMED`、`CANCELLED` 或 `EXPIRED`，也不会自动重新 Preview。

## 3. 恢复、分页与可访问性

- 合法 same-user sessionStorage snapshot 只恢复最小 identity，重新读取 Preview rows 并重新 hydration；不恢复完整 rows 或将 warning metadata 当作当前权威结果。
- 无 snapshot、用户 namespace 不匹配、schema/revision/sessionId/token 不合法时 fail closed，不猜 Session、不读旧 rows，Confirm 请求数为零。
- 现有 401 登录流在同用户再次登录后由 Import 路由重载相同最小草稿；Preview GET 与 hydration 中途 401 都重新读取完整服务端 warning set，且不会新建 Session 或重复 Mapping PUT。
- 375px 浏览器验证覆盖 summary 无页面横向溢出、表格容器横向滚动、可访问 table header、带 label 的 warning checkbox 与键盘 Space 操作。
- 10,000 行模拟以 20 个 `size=500` hydration 请求完成，表格仅渲染 100 个当前页 row。
