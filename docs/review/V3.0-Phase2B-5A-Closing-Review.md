# V3.0 Phase 2B-5A Closing Review

## 范围与决策记录

本 Review 仅覆盖 `BUY`、`SELL` 与 `DIVIDEND` 的追加式冲正，不新增 replacement、任何 OPENING_POSITION 或 Legacy opening 纠正、部分冲正、冲正链、Portfolio、多币种或前端工作。ADR-013 已接受：原始事实与回执保持不可变的 `POSTED` 事实；新增 `POSTED REVERSAL` 事实将其 `original_transaction_id` 目标排除在 replay 有效集合之外。ADR-007 继续作为历史记录；其后续可变 `REVERSED` 语义被取代，而不是被改写。

## 已实现证据

- V12 对历史 `REVERSED`、`reversed_at`、`reversal_reason` 或 `replaces_transaction_id` 数据快速失败，新增追加式字段与命名的部分唯一冲正索引，保留冻结的 `NUMERIC(28,2)` 金额事实精度，并安装事实不可变与冲正审计 PostgreSQL trigger。
- 命令按 `Original InvestmentTransaction -> Account -> Instrument -> Asset` 加锁，插入前执行候选 replay，持久化一条 `REVERSAL`，应用一次 cash delta，执行第二次 replay，恰好更新一次投影元数据，并验证持久化后的 Account / Asset / Reversal 一致性，同时不覆盖 current price 或 market value。
- API 覆盖包括严格 reason / key 解析、拒绝未知 JSON、404 所有权隔离、409 不支持 / 候选冲突语义、same-key replay、different-key / original 冲突、BUY / 部分 SELL / 全部 SELL / DIVIDEND 冲正，以及非活动 Account / Instrument 操作。
- PostgreSQL 17.10 Testcontainers 覆盖包括 V11 到 V12 与 V1 到 V12 migration、Legacy 数据快速失败、字段 / trigger / 不可变约束、replay、并发、四条锁等待超时 / 释放路径和真实 `40P01` 死锁牺牲事务。冲正专项测试使用 `CyclicBarrier`、`pg_stat_activity` 与有界 `Future.get`，没有新增 `Thread.sleep` 顺序控制。
- 真实 PostgreSQL `BEFORE INSERT` 冲正 trigger 失败返回净化后的 500，并在事务外重新检查不存在冲正、余额变更或投影变更。

## 审查结论 — NO-GO

本轮发现的 P0 / P1 已修复：并发 DIVIDEND 可能将 replay validation exception 暴露为 500；事务级 lock timeout 配置得太晚，无法覆盖 Original InvestmentTransaction 加锁。两者现均有回归覆盖。

但是，Phase 2B-5A 要求的故障注入矩阵尚未完成：first / candidate / second replay 注入、投影 affected-row 注入、全部 checker mismatch 注入，以及显式 unknown-unique 冲正测试仍需要专门冲正覆盖。因此最终结论为 **NO-GO**。按既定规则不授权 commit 或 push，且尚未进入 Phase 2B-5B。

## 验证关闭 — 2026-07-29

保留上述历史 NO-GO 作为审计轨迹。缺失的关闭矩阵现由 `InvestmentReversalFailureIntegrationTest` 中 12 个真实 Spring Boot / PostgreSQL 集成测试覆盖：

- 第一次 replay 内部失败：净化后的 500，且没有持久化写入；
- 候选 replay 因后续超卖与孤立 DIVIDEND 产生业务冲突：409 且状态不变；
- 候选 replay 内部失败：净化后的 500 且状态不变；
- 第二次 replay 内部失败：调用顺序证明失败发生在冲正插入和 Account 更新之后，随后事务回滚；
- 投影更新 affected-row 分别为零行与两行：净化后的 500 且完全回滚；
- 持久化 cash、receipt、position 与 projection-metadata 不匹配：净化后的 500 且完全回滚；
- 无关的未知唯一约束冲突：净化后的 500，不会被错误归类为幂等 replay，且完全回滚。

这些测试执行真实 HTTP 异常映射，并从失败事务外检查已提交数据库状态。仅测试使用的 Spring spy 在精确阶段注入失败；生产环境没有测试 flag、失败 endpoint 或 runtime configuration seam。

持久化 cash mismatch 测试发现一个 P1 缺陷：冲正一致性验证使用计算后的余额值，而不是从 PostgreSQL 重新读取的 Account 行。事务 Service 现在将 `updatedAccount.getBalance()` 传给 checker。发现 P0：0。发现 P1：1，修复 1，未关闭 0。

定向冲正验证完成 8 test classes / 61 tests / 0 failures / 0 errors / 0 skipped。Clean backend 运行完成 85 Surefire reports / 407 tests / 0 failures / 0 errors / 0 skipped。它使用 PostgreSQL 17.10 Testcontainers、schema version V12 的 Flyway 10.20.0，以及 Testcontainers 1.20.0。冲正专项测试不含 `Thread.sleep`；clean 运行后没有残留构建拥有的 Maven、Surefire 或 Testcontainers 进程。既存 IntelliJ Maven server 保持不动。
