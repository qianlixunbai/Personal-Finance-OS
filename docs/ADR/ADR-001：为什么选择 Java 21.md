# ADR-001：为什么选择 Java 21

**项目名称：** Personal Finance OS

**ADR 编号：** ADR-001

**标题：** 选择 Java 21 作为项目开发语言

**状态：** Accepted（已采纳）

**日期：** 2026-07-06

**负责人：** 项目维护者

------

# 一、背景（Context）

Personal Finance OS 是一个长期维护的企业级个人金融管理系统。

项目预计持续多个版本迭代，并作为核心软件工程项目长期维护。

因此，开发语言应满足以下要求：

- 长期支持（LTS）；
- 良好的生态；
- 企业广泛应用；
- 优秀的可维护性；
- 成熟的工具链；
- 良好的性能表现；
- 丰富的学习资源。

------

# 二、决策目标（Decision Goal）

选择一种能够长期支撑项目发展的开发语言。

该语言应满足：

- 适合企业级开发；
- 易于维护；
- 与主流框架兼容；
- 有稳定的发展路线；
- 能满足未来数年的版本迭代。

------

# 三、备选方案（Options）

## 方案一：Java 21

优点：

- 长期支持（LTS）；
- 企业应用广泛；
- 与 Spring Boot 3 深度兼容；
- 拥有成熟的生态系统；
- 支持 Record、Virtual Threads、Pattern Matching 等现代语言特性；
- 社区活跃，文档丰富。

缺点：

- 学习成本相对较高；
- 部分旧项目仍停留在 Java 8/17，需要注意版本差异。

------

## 方案二：Java 17

优点：

- 同样属于 LTS；
- 企业使用广泛；
- 稳定成熟。

缺点：

- 缺少 Java 21 的部分新特性；
- 对于新项目，没有充分利用最新 LTS 的优势。

------

## 方案三：Kotlin

优点：

- 语法简洁；
- 与 Java 生态兼容。

缺点：

- 团队主语言并非 Kotlin；
- 企业岗位数量相对较少；
- 增加学习和维护成本。

------

## 方案四：Go

优点：

- 性能优秀；
- 部署简单。

缺点：

- 与项目既定技术栈不一致；
- 企业金融后台生态不如 Java 成熟；
- 不符合本项目的学习与求职目标。

------

# 四、最终决策（Decision）

项目最终选择 **Java 21** 作为唯一后端开发语言。

选择原因：

1. Java 21 是长期支持（LTS）版本，适合长期维护项目。
2. 与 Spring Boot 3 完全兼容。
3. 企业级生态成熟，适合作为求职和工程实践项目。
4. 能够使用现代 Java 特性，提高代码质量和可维护性。
5. 有利于后续扩展、重构及版本升级。

------

# 五、影响分析（Consequences）

## 正面影响

- 获得长期官方支持；
- 提升代码可读性和开发效率；
- 便于引入现代 Java 编程实践；
- 与主流企业开发环境保持一致。

## 负面影响

- 对开发者要求较高，需要熟悉 Java 21 新特性；
- 部分第三方资料仍以旧版本 Java 为例，需要自行适配。

------

# 六、实施计划（Implementation）

为落实本决策，项目将：

- 使用 Java 21 作为唯一后端运行环境；
- 所有开发环境统一配置 Java 21；
- 所有文档、脚本和 CI 配置均基于 Java 21；
- 后续技术选型以 Java 21 为基础。

------

# 七、风险分析（Risks）

可能风险：

- 新特性使用不当导致代码复杂；
- 团队成员（未来）对 Java 21 不熟悉。

缓解措施：

- 优先使用成熟、稳定的语言特性；
- 在 Development Guide 中统一编码规范；
- 保持代码风格一致，避免过度使用语法技巧。

------

# 八、回滚策略（Rollback）

原则上不考虑回滚至 Java 17 或更低版本。

如未来确有必要，应重新评估：

- Spring Boot 兼容性；
- 第三方依赖；
- CI/CD 环境；
- 开发成本。

并新增 ADR 记录新的决策，而不是直接修改本 ADR。
