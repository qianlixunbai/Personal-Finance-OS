# Prompt Guide（AI 协作指南）

**项目名称：** Personal Finance OS

**版本：** v1.0

------

# 一、文档目的

本文档用于规范 AI 在 Personal Finance OS 项目中的协作方式。

统一 Prompt 规范可以：

- 提高开发效率；
- 降低 Token 消耗；
- 保持代码风格一致；
- 避免 AI 重复理解项目；
- 保证长期开发的稳定性。

本规范适用于所有参与项目开发的 AI。

包括但不限于：

- DeepSeek
- ChatGPT
- Codex
- Mimo
- 未来新增的 AI 工具

------

# 二、AI 职责

AI 是开发助手，而不是项目负责人。

AI 可以：

- 理解需求；
- 设计方案；
- 编写代码；
- 修复 Bug；
- 编写测试；
- Review 代码；
- 优化代码。

AI 不负责：

- 修改项目方向；
- 修改业务规则；
- 修改金融规则；
- 擅自重构项目；
- 删除已有功能。

------

# 三、开发原则

每次对 AI 的请求应保持：

- 一个目标；
- 一个模块；
- 一个任务。

避免一次请求多个无关需求。

推荐：

> 完成一个模块，再进入下一模块。

------

# 四、标准 Prompt 模板

所有开发任务建议采用以下模板。

## 任务背景

说明当前模块、版本及目标。

## 当前任务

明确说明本次需要完成的内容。

## 已有条件

列出相关文档、数据库、接口或已有代码。

## 输出要求

明确需要 AI 输出：

- 设计；
- 代码；
- 测试；
- 文档；

或其它内容。

## 限制条件

说明：

不能修改哪些内容。

例如：

- 不允许修改数据库；
- 不允许修改公共 API；
- 不允许修改其他模块。

## 验收标准

明确说明：

什么情况下算完成。

------

# 五、推荐开发流程

每次开发建议遵循以下流程：

阅读相关文档

↓

理解需求

↓

输出设计方案

↓

等待确认

↓

开始编码

↓

自检

↓

Code Review

↓

提交

禁止跳过设计直接生成大量代码。

------

# 六、推荐 Prompt 示例

```
项目：

Personal Finance OS

模块：

账户管理

任务：

新增账户编辑功能。

要求：

仅修改账户模块。

禁止修改数据库结构。

请先输出设计思路，再输出代码。

完成后说明影响范围。
```

------

# 七、Token 优化原则

AI 应尽量减少无效上下文。

推荐：

- 只阅读当前模块相关代码；
- 只提供必要背景；
- 分模块开发；
- 分模块 Review。

避免：

- 每次发送整个项目；
- 每次重新解释项目背景；
- 每次重新生成完整文件。

------

# 八、多 AI 协作

推荐分工如下：

ChatGPT：

- 项目规划；
- 文档编写；
- 架构评审；
- Code Review；
- 技术建议。

DeepSeek：

- 功能开发；
- 模块实现；
- 数据库初稿；
- API 初稿。

Codex：

- 局部修改；
- 重构建议；
- Bug 修复；
- 测试补充。

各 AI 应基于统一文档开展工作，不应各自定义项目规则。

------

# 九、问题处理原则

当 AI 无法确定需求时：

应主动提出问题。

禁止自行猜测业务逻辑。

如发现文档冲突：

应指出冲突。

等待确认后再继续开发。

------

# 十、禁止事项

禁止：

- 一次生成整个项目；
- 擅自修改项目架构；
- 擅自修改数据库；
- 删除已有代码；
- 修改无关模块；
- 擅自改变业务规则；
- 擅自改变金融规则。

------

# 十一、代码输出规范

默认输出顺序：

1. 需求理解；
2. 设计方案；
3. 修改范围；
4. 代码实现；
5. 测试建议；
6. 风险说明。

除非明确要求，否则不要直接输出大量代码。

------

# 十二、上下文管理

每次开发前，应优先阅读：

1. Development Guide
2. AI Rules
3. Financial Rules
4. Business Rules
5. 当前模块 SRS

仅在需要时，再阅读：

- Architecture
- Database
- API

避免无意义扩大上下文。

------

# 十三、协作原则

任何 AI 都应遵循以下原则：

- 文档优先；
- 架构优先；
- 一次只解决一个问题；
- 保持代码一致性；
- 保持命名一致性；
- 保持模块边界清晰。

------

# 十四、最终原则

AI 的职责是协助开发，而不是主导项目。

项目的最终规则以项目文档为准。

当 AI 的建议与项目文档冲突时，应优先遵循文档，并提出修改建议，而不是直接修改实现。

统一规范、统一流程、统一标准，是长期协作开发的基础。
