# v1.4 Quality Hardening Closing Review

本文档记录 Personal Finance OS `v1.4 Quality Hardening` 的正式收尾结论。本阶段覆盖 Dashboard 用户隔离、无效 JWT 测试、数据源可配置性、CI runtime 兼容性和相关 P1 加固，不扩大业务模型。

## 1. 版本目标

v1.4 的目标是：

- 补充 Dashboard 真实 API 双用户隔离验证；
- 补充过期、篡改和格式错误 JWT 的集成测试；
- 支持通过 `DB_URL` 配置完整 PostgreSQL JDBC URL；
- 更新 GitHub Actions runtime 依赖，消除已弃用 runtime；
- 关闭此前 Closing Review 中的 P1 阻塞项：

> `InvalidJwtApiIntegrationTest` 使用不存在的用户 subject，导致过期和篡改 JWT 测试可能假通过。

## 2. 完成范围

### 2.1 Dashboard 用户隔离

- `DashboardApiIntegrationTest` 使用两个真实注册 / 登录用户；
- 分别创建账户、资产、分类和流水数据；
- 使用用户 A 的真实 JWT 请求 Dashboard，验证聚合结果只包含用户 A 的数据，不包含用户 B 的数据。

### 2.2 Invalid JWT 覆盖

- 初始测试覆盖过期、篡改和格式错误 JWT 的统一 `401` 响应；
- 后续加固调整 `InvalidJwtApiIntegrationTest` 的测试夹具和断言覆盖；
- 通过真实注册 / 登录创建存在且为 `ACTIVE` 的用户；
- 使用真实用户 subject 构造过期 JWT；
- 从真实登录 JWT 篡改签名，验证篡改 token 的拒绝路径；
- 保留 malformed JWT 的统一 `401`、无敏感详情响应断言；
- 增加有效 JWT 正向控制，证明同一受保护端点可以被有效用户访问；
- 负向场景验证 `DashboardService` 未被调用。

### 2.3 数据源配置

- `spring.datasource.url` 支持 `${DB_URL:jdbc:postgresql://localhost:5432/finance_os}`；
- `DataSourceConfigurationTest` 覆盖未设置 `DB_URL` 时的默认值和设置完整 JDBC URL 时的覆盖值；
- 用户名和密码仍通过独立环境变量配置，不嵌入 URL。

### 2.4 CI runtime

- GitHub Actions 的 `actions/setup-java` 更新至 v5；
- GitHub Actions 的 `actions/setup-node` 更新至 v6；
- 本项属于 workflow 兼容性维护，不引入新的 CI 能力。

## 3. P1 关闭判断

原测试使用不存在的 subject 时，即使认证过滤器因用户不存在而不建立认证，过期和篡改场景也可能仅凭端点返回 `401` 而通过。

当前测试先完成真实注册和登录，再使用该用户的数据库 id 与真实 JWT：

- 若过期校验失效，过期 token 将可能通过认证并使负向测试失败；
- 若签名校验失效或篡改未生效，篡改 token 将可能通过认证并使负向测试失败；
- 有效 JWT 正向用例证明用户存在、状态有效、Security 链和受保护端点均可正常工作。

因此，原 P1 的假通过路径已被测试设计消除。
