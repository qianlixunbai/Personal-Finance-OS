# v3.0 Phase 2B-3 Closing Review

## 范围

Phase 2B-3 引入显式、单 Asset 的 Legacy 预检、预览和确认式 Opening Position migration。V9 新增快速失败升级检查、Account / Asset 复合外键，以及已入账 opening 的部分唯一索引。

## 已验证边界

- `totalCost` 继续作为权威值；calculator 重建结果精确一致。
- Preview 对 source version 与 request hash 签名，不写入数据。
- Confirm 使用 Account -> Instrument -> Asset 锁顺序、replay 重建、幂等恢复与余额不变性一致性检查。
- 不修改 `Account.balance`；不新增公开 BUY、SELL、DIVIDEND、Portfolio、批量 migration 或前端工作流。

## 已知限制

Phase 2B-4 仍不在范围内。Legacy 零持仓需要后续归档 / 纠正流程处理，而不是创建 opening transaction。

## 验证关闭历史

1. 初始功能实现已经完成，但专门的故障注入和双线程并发证据不足。
2. 因此，首次关闭评估结论为 **NO-GO**。
3. 后续轮次增加了聚焦回滚、Web 响应净化和并发操作覆盖。
4. 这些轮次发现并修复了两个生产缺陷：
   - 使用同一幂等键的并发请求可能先等待锁，随后被错误地判定为过期 preview；
   - `updatedAt` 参与 `sourceVersion`，导致仅更新参考价格也可能错误阻止 migration。
5. 最终聚焦测试覆盖临时绑定、opening 插入、投影写入与 Consistency Checker 回滚；Web 500 净化；锁等待超时与释放；same-key / different-hash 和 different-key / same-Asset 行为；以及 migration 与 close、delete、updatePrice、Account 停用、Instrument 停用之间的竞态。
6. `LegacyOpeningMigrationConcurrencyIntegrationTest` 使用真实线程、`CyclicBarrier` 与有界 `Future.get`，通过 **12/12**；不使用 `Thread.sleep` 定义顺序。
7. Consistency Checker 失败路径会回滚，并返回净化后的 HTTP 500 响应。
8. PostgreSQL Account 行锁等待超时返回净化后的 HTTP 409；在超时前释放锁则允许 migration 成功。
9. 竞争的 close、delete、price-update、Account-deactivate 与 Instrument-deactivate 操作均不会留下部分 migration 状态。
10. `sourceVersion` 包含实质 migration 输入（asset / user identity、quantity、cost 字段、currency / type、account / instrument binding、position mode / status 与 projection version），排除仅供参考的 `currentPrice`、`marketValue` 和通用 `updatedAt`；实质变更返回 409，且不产生 opening 或部分绑定，而仅参考值变更时仍可确认。
11. 最终完整命令 `backend\\mvnw.cmd clean test` 在真实 PostgreSQL 17 Testcontainers 上运行，完成 73 test classes / 318 tests、0 failures、0 errors、0 skipped。
12. P0 与 P1 发现数均为零。
13. 最终结论为 **GO**。
