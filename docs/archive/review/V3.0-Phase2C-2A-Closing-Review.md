## 2. 已确认的内部读取实现

- Position list 只读取 `TRANSACTION_DRIVEN` Asset 投影，默认 `OPEN`，支持稳定的 `(instrumentId ASC, accountId ASC, positionId ASC)` seek pagination。
- Logical transaction list 在单条 PostgreSQL 查询中折叠 original、standalone reversal、grouped reversal、replacement fact 与 correction envelope。
- 默认逻辑列表使用 `(effectiveTradeTime DESC, logicalTransactionId DESC)`；replacement 使用 original ID 和 original trade time。
- `type`、`correctionStatus`、`from/to`、Position、Account 与 Instrument filter 均应用于最终逻辑行。
- 所有资源查询在 SQL 层带 `user_id` ownership；跨用户和不存在的过滤资源使用相同安全 404。
- 多查询组合 Service 使用只读 `REPEATABLE READ`；没有逐行 replay、N+1、写状态、行锁或 Provider 调用。
- 金融值按冻结 scale 输出 JSON string；默认列表 DTO 不公开 correction reason、物理 correction ID、receipt、request hash、幂等键、digest、group ID 或 trace。

## 4. Standalone reversal PostgreSQL 证据

`foldsStandaloneReversalIntoOneFilteredRedactedLogicalEvent` 在 Testcontainers PostgreSQL 17.10、Flyway v13 上建立真实 original BUY 与 standalone `REVERSAL`：

- 默认列表只返回 original ID 对应的一条 logical event；reversal physical fact 不作为第二条普通交易出现；
- logical ID、业务类型、金额、数量与有效时间均来自 original；
- `correctionStatus=REVERSED`、`effective=false`，`correctionCreatedAt` 等于 reversal 的真实 `created_at`；
- `type`、`correctionStatus`、`[from,to)` 与 Position filter 对折叠后的最终逻辑行生效；
- 响应字段使用精确白名单断言，不含 reversal ID、reason、receipt、request hash、幂等键或内部 correction 字段；
- 跨用户 original/reversal 绑定被 V12 复合 ownership 约束拒绝，外部用户列表为空，不泄露关系或资源存在性。

## 5. Replacement PostgreSQL 证据

`foldsReplacementIntoOriginalIdentityAndEffectiveTimeWithReplacementValues` 在同一事务中建立真实 original、grouped reversal、same-type replacement fact 与 correction envelope，并由 V13 deferred FK / constraint trigger 在提交时校验：

- 默认列表只返回 original logical slot；grouped reversal 与 replacement fact 均不单独出现；
- `logicalTransactionId` 使用 original ID，`correctionStatus=REPLACED`，`effective=true`；
- quantity、unit price、gross、fee 与 net 使用 replacement 的有效业务值，旧 original 业务值不再重复出现；
- `effectiveTradeTime` 保持 original trade time，`correctionCreatedAt` 使用 envelope 的真实 `created_at`；
- 较晚 correction time 不会让 replacement 跳到较新普通交易之前；
- `type` filter 使用最终同类型有效值，时间过滤使用 original/effective trade time；
- 精确响应字段白名单证明 grouped reversal ID、replacement physical ID、correction group ID、request hash、幂等键、digest 与 trace 均未公开。

## 6. 混合 logical cursor 分页证据

`paginatesMixedLogicalEventsByEffectiveTimeAndLogicalIdWithoutPhysicalFactSlots` 将普通、REVERSED 与 REPLACED 三类 logical event 放入同一数据集：

- 三条 original 使用同一 `effectiveTradeTime`，按 logical ID DESC 稳定打破并列；
- page size 为 2 时，第一页返回 REPLACED 与 REVERSED logical slot，第二页只返回剩余普通 logical slot；
- 两页合并无重复、无遗漏；grouped reversal 与 replacement fact 不消耗逻辑分页位置；
- 第一页后插入更新的普通交易，第二页不重复第一页记录，也不错误穿越既有 cursor 边界；
- 数据库同时存在 7 条物理事实，其中 2 条属于 replacement group，而 cursor 仍只按 logical row 工作。

## 7. 关系异常与数据库约束证据

当前 schema 不允许提交不完整 replacement group，因此读取层不会观察到部分或伪造的 committed logical event：

- V12 `fk_investment_transactions_original_binding` 以 `(user_id, account_id, asset_id, original_transaction_id)` 绑定 original；
- V13 `fk_investment_transactions_correction_group_command` 为 `DEFERRABLE INITIALLY DEFERRED`；
- V13 的 `trg_validate_investment_replacement_group_complete` 与 `trg_validate_investment_replacement_command_complete` 均为 deferred constraint trigger；
- 既有 `InvestmentReplacementMigrationIntegrationTest` 已覆盖 incomplete group commit rejection；
- 新增 `databaseRejectsIncompleteReplacementGroupsBeforeTheyCanReachTheReadModel` 再次证明只有 replacement fact、没有 envelope 的 group 在 commit 时被拒绝并完整回滚，读取只返回未纠正 original。

公开异常仍由全局异常处理器脱敏；SQL、constraint 名称、堆栈与物理 ID 不进入公共响应。
