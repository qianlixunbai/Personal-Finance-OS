# v3.0 Phase 2B-4A Closing Review：BUY / SELL 写路径

## 范围与结果

Phase 2B-4A 只交付对已执行 BUY 与 SELL 事实的手工记录，不新增 DIVIDEND、纠正、Portfolio、下单、券商集成或前端 BUY / SELL 工作。

**最终决策：GO。**

## 初始运行时阻塞

此前运行时验证被正确阻塞，因为配置的本地 `finance_os` 数据库是非空 Legacy schema，且没有 `flyway_schema_history`。Flyway 拒绝自动 migration，而没有错误地为其建立 baseline。期间没有执行 baseline、repair、schema 操作或数据删除。

后续本地数据库检查发现，`finance_os_dev` 已有 V1--V10 且没有投资事实，但包含一个现有用户。为隔离 runtime smoke 数据并保留可恢复副本，仍对其执行备份，并重建为全新的开发数据库。

## Runtime smoke 证据

使用并刻意保留了专用本地 smoke 数据：

- User：`phase2b4a-smoke-20260727184300@example.local`。
- Account：`Phase 2B-4A Smoke Brokerage`（`BROKERAGE`、`CNY`、ACTIVE）。
- Instrument：`SMOKE`（`FUND`、ACTIVE、CNY quote currency）。

真实 JWT 保护 API 流程验证了：

1. First BUY 创建一个交易驱动 Asset、一条 POSTED BUY、不可变回执字段和负账户余额。
2. 完全相同的 first-BUY 重试返回原 Transaction 与 Asset，且 `idempotentReplay=true`，没有新增事实或余额变更。
3. 后续 BUY 复用同一 Asset 并更新其投影。
4. 部分 SELL 产生 released cost 13.83 与 realized PnL 15.17，同时保持 OPEN 状态。
5. 全部 SELL 将 quantity、average cost 与 total cost 清零，关闭 Position 且不留舍入残差。
6. 后续 BUY 重新打开同一 Asset，没有创建另一个 Position。
7. 最终 smoke Account balance 为 12.50；数据库 cash-delta 重算结果精确一致。
8. 五条已入账事实（三条 BUY、两条 SELL）使用五个不同幂等键、五个规范 request hash 与五份完整回执。
9. Same key 搭配不同请求返回 HTTP 409，且不泄露 request-hash 或幂等数据。
10. SELL quantity 超过锁定 replay position 时返回 HTTP 409，不产生事实、余额或 Position 变更。

最终 Asset 的 quantity 为 `1.00000000`、average cost 为 `15.00000000`、total cost 为 `15.00`、累计 realized PnL 为 `27.50`、status 为 `OPEN`、projection version 为 `5`、last transaction ID 为 `5`，与已记录回执 / replay 序列一致。

## 已审查的写路径保证

- ADR-011 继续作为治理设计：Account -> Instrument -> Asset 锁顺序、CNY-only 账务、允许负余额、不可变回执、服务器负责入账时间，以及事务整体回滚。
- `AccountBalanceService` 继续作为 Account balance 的生产写入者。
- BUY / SELL 回执快照不可变；幂等 replay 恢复原始结果，而不是当前投影值。
- 所有写路径锁查询均限定用户范围；投影更新后调用生产一致性检查。
- 未引入 DIVIDEND、correction / reversal / replacement 公开写 API、Portfolio 工作或前端变更。
