## 2. 实现范围

- 新增受保护路由 `/transactions/import`，并在“交易流水”页的 `PageHeader.actions` 中提供“导入流水”入口。
- 新增 Import shell 与六段状态轨。React transient state 只描述上传、mapping discovery 和 mapping submit 的进度；Session status、revision、token 与 Preview-ready 状态始终从后端 response 替换，不在前端自增或合并 stale state。
- Upload 只接受 `.csv` / `.xlsx`，给出本地空文件、扩展名和 5 MiB 提示；请求固定使用 `AUTO`，后端仍是内容、安全和格式校验边界。
- Mapping 使用 target-first 的列选择、明确 `IGNORE`、同一 Session 的 discovery PUT → rows scan → formal PUT 两阶段流程。rows discovery 固定 1-based、`size=500`、至多 20 页；只保留 trim + NFC 去重后的类型/账户/分类来源值和最小类型关联，不保留完整 rows。
- Account 选项只来自当前 `/accounts` response 且仅可选择 `ACTIVE` / `CNY` 项；Category 选项只来自当前 `/categories` response，不提供自由 ID 输入或自动创建。
- 正式 mapping response 到达后整包替换 revision，并仅显示“预览边界”；页面没有 Confirm button、idempotency key、金融 POST 或前端余额计算。

## 3. API 与状态边界

本阶段实际 API 为：

- `POST /api/v1/imports/transactions/preview`（multipart: `file`、`request`）
- `PUT /api/v1/imports/transactions/{sessionId}/preview`（multipart: `mapping`）
- `GET /api/v1/imports/transactions/{sessionId}/rows?page=&size=`
- `DELETE /api/v1/imports/transactions/{sessionId}`（仅放弃尚未 Confirm 的当前会话）
- 复用既有 `GET /api/v1/accounts`、`GET /api/v1/categories`。

API adapter 继续复用唯一 Axios client、JWT interceptor 与既有 401 清理/登录跳转，不新增客户端或认证体系。服务端错误 message 通过既有页面内 alert 展示，未显示 raw stack trace。

`sessionStorage` 仅保存 `finance-os:transaction-import:draft:v1:{userId}` 的最小 snapshot：会话标识、revision、公开 summary/digests、mapping、文件展示 metadata 与 expiry；不保存文件 bytes、完整 rows、JWT、余额或 receipt。恢复前校验 schema、当前 user、UUID、revision、expiry 与 token 规则；缺少或无效 snapshot 时明确要求重新开始。显式 logout 只清当前 user 的 Import snapshot。

- 所有 filename、header、source value 和后端 message 均经 React text rendering；未使用 `dangerouslySetInnerHTML`。
- file input、列选择器及每个 value mapping select 均有可访问 label；状态/错误用文本加 `role=status/alert`，table header 使用 `scope`。
- Mapping 在 768px 以下改为单列；进度轨在移动端为三列网格，表格保留自身横向滚动，未创建第二套页面。
- A 阶段不会发送 `POST /imports/transactions/{sessionId}/confirm`，不会创建 Transaction 或修改 Account.balance，也不会生成/保存 previewToken 的 Confirm intent。
