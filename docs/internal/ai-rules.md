# AI 协作规则

清晰、低风险任务采用“检查 → 最小修改 → 匹配验证 → 仅在要求时提交”。不要为小任务自动创建长计划、worktree、大规模多 Agent 或重复 review。

金融计算、用户隔离/安全、migration、事务、并发和锁必须先核对设计并严格验证；已发现 bug 或敏感不变量应补回归测试。不得虚称测试、构建、smoke 或 review 已运行。

金融真值以后端与 migration 为准；阅读顺序为代码/migration → ADR → 最新 Closing Review → 活文档。架构冻结，架构级变更需要 ADR；不得把未来能力写成已实现。不得读取、修改、暂存、删除或提交未授权、用户拥有、历史或范围外文件。

已有完整方案时直接执行，不重复 brainstorming。通常一次实现 review 加一次修复后复验即可；不为非阻塞 P2/P3 无限循环。按任务风险选择模型，不把具体模型永久绑定某类职责。
