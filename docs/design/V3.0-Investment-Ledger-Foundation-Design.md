# v3.0 Phase 1 Investment Ledger Foundation Design

**状态：** 已实施，待独立验收

## 目标与边界

本阶段建立投资事实、持仓重建和后续一致性校验的基础。`InvestmentTransaction` 是事实，`Asset` 是当前持仓受控投影，`Account.balance` 是现金余额投影；Market Quote、FX 与 Reference Valuation 不得修改交易、成本或现金余额。

已实施：ADR-007、规则冻结、`BUY` / `SELL` / `DIVIDEND` / `OPENING_POSITION` 领域类型、纯 BigDecimal Calculator、内存 replay、V4 migration、Entity/Mapper、Asset 兼容投影字段和 PostgreSQL 约束测试。

未实施：Controller、公开 API、真实交易写入、余额联动、行锁、幂等写入 Service、旧 Asset Opening Position 迁移、前端和 Dashboard 改动。

## 计算与 replay

成本法为加权平均。BUY 将 gross、fee、tax 计入成本；SELL 按比例释放成本，全部卖出时释放全部剩余成本；DIVIDEND 不改变持仓成本；OPENING_POSITION 不产生现金 delta。所有计算使用 `BigDecimal`，金额 scale 为 2，数量/平均成本 scale 为 8，除法使用 `HALF_UP`。

replay 只在内存中运行，按 `tradeTime ASC, id ASC` 排序，跳过 `REVERSED` 交易，并在中途超卖时整体失败。

## 持久化

V4 新增 `investment_transactions`，包含交易类型、状态、数量、金额、时间、来源、幂等键、request hash、冲正/replacement 关联和审计时间。`(user_id, idempotency_key)` 唯一；交易到 Asset 和 Account 采用组合用户外键，阻止跨用户引用。`assets` 只增加可兼容 legacy 数据的 `account_id`、成本/已实现盈亏、投影状态、最后交易、版本和 `position_mode` 字段。

现有 Asset、Account、普通 Transaction、Dashboard、Market Quote、FX 与 Reference Valuation 行为均未改变。
